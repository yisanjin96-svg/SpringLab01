# SpringLab01

予約システムを作って同時性を学ぶ。

pakage.domain.Facility
には＠getterだけ使用する、特定メソッドを通して値が変わるよう、
자바에서는 게터/세터로 값을 주고 받는게 기본이고, 특정 메서드를 통해 세터의 역할을 수행하면서,
값이 함부로 바뀌지 않도록 조치한다.

엔티티
정확한 정의 : DB데이터 한 줄(행을) 자바 객체로 표현한 것
동작 원리로서는 @Entity로 선언시 JPA가 이 클래스를 보고 이건 DB테이블과 매핑되는구나라고 판단한다.

문장1
private의 사용이유
    흔한 캡슐화의 이유로 Facilty 클래스 밖에서 facility.name = "불명값"이 들어갈 수 없다.
　   例2에서 생성자를 만들어 두었고, 이 생성자를 통해서만 값이 변경될 수 있도록 제한을 둔 이유라고 생각해야한다.
문장2
    문장1에서 지적사항이 있다.
    생성자에 값을 변경하는게 아닌, 생성자에 초기값을 설정하는게 정확한 설명이다.
    일명 초기화라고 정의한다. 객체가 생성된 이후에는 이 값을 변경할 수 없다.
    문장1의 논리처럼 값을 변경하기 위해서는 값을 변경하기 위한 메서드를 따로 구현해야한다.
문장3
    정확한 논리를 위해 값이 실제로 필드에 들어가는 순간은 new Facility가 선언된 시점.
    그때 this.name = name에 값이 들어가게 된다.
    값 대입 시점이 헷갈리는 이유는 new Facility(...)가 100번 선언되면 
    내가 착각하고 있는 언제든지 값이 들어갈수 있는 가능성의 전제가 되겠지만 그럴일은 없으니.
    다시 정리하자면
값이 실제로 필드에 들어가는 순간은 new Facility(...)가 호출된 시점.

참고로 해당 엔티티는 세터가 빠져있다. 불변객체 변하지 않는 객체를 만들기위해
전제 > 초기값이 설정되고 나서의 불변한다.
