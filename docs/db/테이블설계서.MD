# 테이블 설계서 (HOSHIMOTO AIR)

> 원본: `doc/excel/테이블정의서_HOSHIMOTO_AIR.xlsx` (v1.1, 2026/09/23)
> 범례: ○ = 해당 / NN = NOT NULL / 개인 = 개인 정보

## 테이블 목록

| No | 논리명 | 물리명 | 개요 | 관련 테이블 |
|---|---|---|---|---|
| 1 | 회원 | `member` | 서비스 이용 회원 정보. 삭제는 논리 삭제 | － |
| 2 | 항공편 | `flight` | 운항 항공편 1편(편명 + 출발 일시) | airport (N:1), seat (1:N), flight_fare (1:N) |
| 3 | 공항 | `airport` | 공항 코드(IATA)·공항명·도시명 마스터 | flight (1:N) |
| 4 | 좌석 | `seat` | 항공편별 개별 좌석(12A 방식)과 예약 상태 | flight (N:1) |
| 5 | 항공편 운임 | `flight_fare` | 항공편·좌석 등급별 성인 1명 운임 | flight (N:1) |

```
airport 1 ──< N flight 1 ──< N seat
                       1 ──< N flight_fare
member (독립)
```

## 설계 이유 (요약)

| No | 대상 | 결정 | 이유 |
|---|---|---|---|
| 1 | 공통 | 컬럼 접두사는 PK에만 붙인다 | FK가 같은 이름이 되어 조인 관계가 한눈에 보임 (seat.flight_id = flight.flight_id) |
| 2 | 공통 | 모든 테이블에 created_at / updated_at | 장애 조사 추적용. JPA Auditing으로 자동 입력 |
| 3 | 공통 | Enum은 STRING으로 저장 | ORDINAL은 Enum 순서 변경 시 기존 데이터 의미가 바뀜 |
| 4 | member | name_kanji NULL 허용, name_kana 필수 | 외국인은 한자 이름이 없고, 검색·정렬 기준은 가나 |
| 5 | member | 나이 대신 birth_date | 나이는 매년 바뀜. 탑승일 기준으로 계산 |
| 6 | member | telephone은 VARCHAR | 숫자형이면 선두 0이 사라짐 |
| 7 | member | email 부분 UNIQUE | 논리 삭제 회원의 메일로 재가입 가능하게 |
| 8 | member | 논리 삭제 | 예약 이력이 회원을 참조함 |
| 9 | flight | 좌석 연관은 seat 쪽 @ManyToOne만 (단방향) | 항공편 조회 시 좌석 대량 로딩·JSON 순환 참조 방지 |
| 10 | flight | (flight_number, departure_at) 복합 UNIQUE | 같은 편명은 매일 운항함 |
| 11 | flight | 공항 코드는 airport FK | 존재하지 않는 공항 코드를 DB에서 차단 |
| 12 | airport | PK는 airport_code (자연키) | IATA 코드는 사실상 불변이고, 조인 없이도 공항을 알 수 있음 |
| 13 | seat | 좌석 1개 = 1행 | 좌석 지정과 행 단위 잠금으로 중복 예약 방지 |
| 14 | seat | 남은 좌석 수는 COUNT로 계산 | 이중 관리로 인한 불일치 방지 (인덱스로 보완) |
| 15 | seat | status는 BOOLEAN이 아닌 Enum | "임시 확보" 같은 상태를 추가하기 쉬움 |
| 16 | flight_fare | 운임은 별도 테이블 | seat에 두면 제3정규형 위반 (금액이 좌석 수만큼 중복) |
| 17 | flight_fare | amount는 INTEGER | 엔화는 소수점이 없고, FLOAT는 오차가 생김 |

## 보류 사항

- seat에 `version` 컬럼(낙관적 잠금) 추가: 예약 확정 기능을 만들 때 넣는다 (X1~X3는 조회만 함)
- 로마자 성명의 성·이름 분리, 소아·유아 운임: 발권 요건과 운임 규칙이 정해진 뒤 결정
- 예약(reservation) 테이블: 아직 정의되지 않음
